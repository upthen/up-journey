# Spec: up-journey v1 — 家庭旅游记录应用

Status: ready-for-agent

## Problem Statement

一家人这些年走过不少地方，照片散落在 NAS 的共享相册里，回忆却没有一个"家"：想回顾某次旅行只能翻文件夹，想告诉亲友"我们都去过哪儿"没有一张能拿出手的地图，孩子问"我们去过多少地方"答不上来。需要一个能录入、能展示、能传承家庭记忆的应用，部署在自己的 NAS 上，数据完全自持。

## Solution

一个部署在绿联 NAS Docker 里的家庭旅游记录应用 **up-journey**：

- **管理端**（`/admin`）：录入一次旅行的标题、日期、途经城市、景点、按天行程、同行家人、标签，以及一篇富文本游记；景点图片不重复上传，直接指向 NAS 共享相册里的子目录。
- **展示端**：杂志编辑风的三个页面——首页（旅行年数/省/市/景点等数字统计 + 最近旅行）、足迹总览（中国地图省份着色 + 城市标记 + 旅行卡片列表 + 总时间轴）、单次旅行详情（富文本游记 + 按景点分组图库 + 景点级路线小地图）。移动端优先响应式，随时拿手机给亲友展示。

图片的唯一数据源始终是 NAS 共享相册：应用实时扫描、按需生成缩略图缓存，原图永不改动。

## User Stories

**录入（管理端，家庭记录者）**

1. 作为家庭记录者，我想录入一次旅行（标题、起止日期、卡片摘要、富文本游记正文），这样家庭记忆有了结构化的载体。
2. 作为家庭记录者，我想把旅行保存为草稿、写完再发布，这样半成品不会出现在展示端。
3. 作为家庭记录者，我想在录入旅行时通过搜索/级联选择添加途经城市（省 → 市），这样零学习成本就能完成地图数据的录入。
4. 作为家庭记录者，我想为城市下的景点配置共享相册子目录（如 `2024云南/大理洱海`），这样照片留在相册里就能被应用引用，无需上传。
5. 作为家庭记录者，我想对想精确定位的景点（如西湖、洱海）在小地图上点一下落点，不想精调的默认跟随城市中心，这样录入负担几乎为零、地图又足够准。
6. 作为家庭记录者，我想为旅行添加按天行程（D1 昆明→大理…），这样时间轴能展示到天级细节。
7. 作为家庭记录者，我想勾选每次旅行的同行家庭成员，这样首页能出"带娃出行 N 次"这类有温度的统计。
8. 作为家庭记录者，我想给旅行打标签（亲子、自驾、海岛…），这样卡片信息更丰富、将来可筛选。
9. 作为家庭记录者，我想从该次旅行全部景点图片中挑选一张作封面，这样卡片和首页有体面的视觉入口。
10. 作为家庭记录者，我想在富文本编辑器里"从相册选图插入"插图，这样游记图文并茂且图片仍单一来源。
11. 作为家庭记录者，我想维护家庭成员（姓名/称呼）和标签字典，这样录入时有干净的选项可选。
12. 作为家庭记录者，我想编辑和删除已有旅行，这样录入错误可以修正。
13. 作为家庭记录者，我想在管理端按年份/标签/城市筛选旅行列表，这样记录多了以后仍然好找。
14. 作为家庭记录者，我想录入境外旅行（国家 + 城市名 + 可选坐标），这样出国记录不缺席、统计里能看到"去过 N 个国家"。

**展示（展示端，家人与亲友访客）**

15. 作为访客，我想在首页看到"旅行了 N 年、去过 N 个省、N 个市、N 个景点、N 个国家、N 次旅行、累计 N 天"这样的数字统计，这样一眼看到这个家庭的足迹厚度。
16. 作为访客，我想在首页看到最近一次旅行的大图卡片，这样最新的回忆有最显眼的入口。
17. 作为访客，我想在足迹总览看到一张中国地图，去过的省份着色、城市打标记、旅行路线按时间连线，这样"我们去过哪儿"一图胜千言。
18. 作为访客，我想在地图下方浏览旅行卡片列表（封面 + 摘要 + 标签 + 日期），这样能快速找到感兴趣的某次旅行。
19. 作为访客，我想在卡片列表下方沿着时间轴（旅行为主节点、天为子节点）纵向回顾，这样家庭旅行的编年史一目了然。
20. 作为访客，我想点进单次旅行读完整的富文本游记，这样能沉浸式重温那次出发。
21. 作为访客，我想在旅行详情页看按景点分组的图库，这样"在大理拍了什么"结构清晰。
22. 作为访客，我想在旅行详情页看到该次旅行的景点级路线小地图，这样行程走向直观可感。
23. 作为访客，我想在手机上流畅浏览全部页面，这样随时随地能和家人朋友分享。

**图片体验**

24. 作为访客，我想卡片列表瞬间加载（缩略图档），这样翻页浏览不卡顿。
25. 作为访客，我想点开大图看到高清版（大图档 ~1600px），这样照片细节不损失。
26. 作为访客，我的照片无论是 HEIC 还是 JPG、无论旋转方向如何，都能正确显示，这样旧照片无需人工处理。

**运维（NAS 所有者）**

27. 作为 NAS 所有者，我想用一份 docker-compose 在绿联 UGOS Pro 上一键拉起 nginx + api + mysql 三容器，这样部署和升级简单可控。
28. 作为 NAS 所有者，我想通过 .env 配置共享相册挂载路径、数据库密码等环境差异，这样同一份 compose 通吃本地开发和 NAS 生产。
29. 作为 NAS 所有者，我希望应用绝不修改/删除相册原图（只读引用 + 独立缩略图缓存卷），这样数据主权永远在相册。
30. 作为 NAS 所有者，我想让非 Safari 浏览器也能看 HEIC、外网设备离线也能看地图（全离线方案），这样不依赖任何外部服务。
31. 作为 NAS 所有者，我将来把应用反代到我的公网域名时，只需打开预留的"访客密码 + 管理员密码"开关即可，这样不用改架构。

## Implementation Decisions

以下决策均来自 2026-09-01 的需求访谈，已与产品所有者逐条确认。

**技术栈**

- 前端：Vue 3 + TypeScript + Vite **单一 SPA**（展示端 + `/admin` 内嵌管理端，不拆两个应用）。
- 组件库：Element Plus（管理端表单/表格/日期等主场）；展示端用 Tailwind CSS 自定义排版，视觉不被组件库默认风格绑架。
- 地图：ECharts + 中国 GeoJSON（省级多边形），不用在线瓦片、不用地图 API key，完全离线。
- 富文本：WangEditor 5，配"从相册选图插入"的自定义入口（选图器浏览已配置的相册目录）。
- 后端：FastAPI + SQLAlchemy 2.0 + Pydantic v2，容器内 Python 3.12。
- 数据库：MySQL 8，utf8mb4，专用容器，不对外暴露端口。
- 字体：思源宋体（Noto Serif SC）做标题，正文用无衬线，构成杂志编辑风的骨架。

**数据模型（Trip 为中心）**

- `family_member`：家庭成员（姓名、称呼）。
- `tag`：标签字典。
- `trip`：一次旅行——标题、slug、起止日期、封面（引用相册图片）、卡片摘要、富文本正文、草稿/发布状态；多对多关联 members 与 tags。
- `trip_city`：旅行与城市字典的有序关联（支持一次多城市顺序，供路线连线）。
- 城市字典：内置中国行政区划数据——34 个省级单位（含港澳台）+ 全部地级市，每市带中心经纬度，省份名与地图 GeoJSON 名称严格一致；境外城市不入字典，录国家 + 城市名 + 可选坐标。
- `trip_day`：按天行程（属于 trip，天序、日期、标题、备注）。
- `attraction`：景点——名称、所属城市、**共享相册子目录（相对路径）**、可选精确坐标（未填则跟随城市中心）。

**图片管线**

- 唯一数据源 = NAS 共享相册目录（Docker 只读挂载）；录入时配置目录的相对路径。
- 后端按需生成两档 JPEG 缓存：缩略图 ~400px、大图 ~1600px（EXIF 旋转自动纠正、HEIC 自动转码），缓存写入应用自己的数据卷，原图永不改动。
- API 层校验所有图片路径必须落在挂载根内，拒绝目录穿越（`../` 等）。
- 相册内容增删后实时生效（无入库同步任务，请求时扫描 + 缓存命中）。

**统计口径**

- 旅行年数 = 当前自然年 − 首次旅行年份。
- 省数 = 去过的省级行政区去重（直辖市同时计入省、市两项）。
- 市数 = 地级市去重；景点数按"城市 + 名称"去重；国家数 = 境外记录的国家级去重。
- 另计：旅行次数、累计旅行天数、带娃出行次数。

**部署**

- 绿联 NAS（192.168.1.18，UGOS Pro）docker-compose 三容器：nginx（前端静态 + API 反代，对外端口 8100）、api、mysql。
- 共享相册宿主机路径、数据库口令等全部走 `.env`；本地开发用 Docker Desktop 跑 MySQL 8，同一套 compose。

**安全**

- v1 客户端与管理端均不做鉴权（纯局域网使用）。
- 所有 admin API 挂在独立的 FastAPI 路由依赖下，前端预留路由守卫位——未来反代公网前启用"访客密码 + 管理员密码"开关即可，无需改架构。
- 部署文档显著警示：挂公网前必须开启鉴权。

## Testing Decisions

- 唯一测试接缝 = 后端 HTTP API（FastAPI TestClient）：CRUD、统计口径、足迹聚合、图片管线（缩略图生成、HEIC 转码、EXIF 旋转、目录穿越拦截、404）全部从 API 表面验证，只测外部行为不测实现。
- 测试库用 SQLite 内存（毫秒级、零依赖）；部署脚本对 NAS 上真 MySQL 实例跑 health/stats 冒烟，验证方言无偏差。
- 前端不写自动化测试：靠高保真原型对齐 + 浏览器人工验收（Playwright E2E 列入 v2 候选）。

## Out of Scope

- 鉴权的实际实现（v1 只做架构预留）。
- 世界地图图层与境外点上图（v2；数据模型已预留国家字段，届时免迁移）。
- 在线瓦片地图 / 地理编码 API / 高德等外部地图服务集成。
- 内置热门景点坐标库。
- 相册应用（Immich、群晖 Photos 等）的 API 集成。
- 前端自动化测试（单元/E2E，v1 靠浏览器人工验收）。
- 多用户体系、评论、分享页等社交能力。
- 图片上传能力（应用永远只引用相册，不做第二个相册）。
