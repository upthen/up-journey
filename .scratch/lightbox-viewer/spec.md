# Spec: 灯箱升级——照片大图查看器

Status: ready-for-agent

来源：grilling 访谈共识（2026-09-06，三轮问答，决策树已清空）。

## Problem Statement

家人与亲友在展示端旅行详情页点开照片看大图时，灯箱只能看一张：想看下一张要么关掉再点、要么知道隐藏的键盘快捷键；照片想看清细节（一张脸、一块碑文）没有任何缩放手段；横图竖看也没有旋转。管理端记录者在相册浏览器里选图时同样无法放大预览，只能凭缩略图猜内容。访客在手机上无法用最自然的手势（滑动、捏合）翻看和放大照片。

## Solution

将全局灯箱升级为完整的照片查看器：翻页（键盘 ←/→、屏幕两侧箭头按钮、手机左右滑动）、缩放（滚轮缩放、双击 1x↔2x、双指捏合、放大后拖拽平移、一键"适合窗口"复位）、90° 步进旋转（纯查看辅助，不落库）。桌面底部胶囊工具栏集中计数与操作，手机隐藏侧箭头靠手势。配套把后端高清档从 ~1600px 提到 ~2600px，让放大后仍然清晰。管理端相册浏览器顺手接入同一灯箱。

## User Stories

1. 作为访客，我想在灯箱里点击屏幕两侧的箭头切换上一张/下一张，这样不知道快捷键也能连续看完整组照片。
2. 作为访客，我想用键盘 ←/→ 在照片组内翻页，这样桌面浏览不用离开键盘。
3. 作为访客，我想在手机上左右滑动切换照片，这样单手就能快速翻看相册。
4. 作为访客，我想在 1x（适合窗口）状态下横滑超过阈值才翻页、轻拨回弹，这样不会因为随手一碰就跳张。
5. 作为访客，我想用鼠标滚轮缩放照片，这样与系统图片查看器的习惯一致。
6. 作为访客，我想双击照片在"适合窗口"与 2x 之间切换，这样两步就能看清大部分细节。
7. 作为访客，我想在手机上双指捏合缩放照片，这样放大是最自然的手势。
8. 作为访客，我想在放大后拖拽平移查看照片各处，这样能巡视整张图。
9. 作为访客，我想放大后单指拖动只平移不翻页，这样巡视照片时不会意外跳到下一张。
10. 作为访客，我想点"适合窗口"一键回到完整视野，这样迷路时随时归位。
11. 作为访客，我想把横图旋转 90° 观看，这样竖持手机也能舒适看横构图。
12. 作为访客，我想在底部工具栏随时看到"第几张/共几张"，这样知道自己在相册的什么位置。
13. 作为访客，我想翻页和关闭灯箱后自动复位缩放与旋转，这样每张照片都以干净的默认状态呈现。
14. 作为访客，我想灯箱里单张照片（无组）时隐藏箭头和计数但仍可缩放旋转，这样界面不出现无用的死按钮。
15. 作为访客，我想翻页时有轻微淡入过渡而非生硬跳变，这样浏览体验是连贯的。
16. 作为访客，我想灯箱加载失败时仍可翻页和操作，这样一张坏图不会困住整组浏览。
17. 作为访客，我想照片放大到约 130% 仍然清晰，这样"看清细节"是真实可用的能力而非口号。
18. 作为家庭记录者，我想在管理端相册浏览/选图时点开大图，用同一套缩放旋转查看，这样选封面和配图时不用先发布再回展示端检查。
19. 作为 NAS 所有者，我想高清档尺寸由配置决定且调整后缓存自动失效重建，这样改画质参数不需要手动清缓存。
20. 作为 NAS 所有者，我想查看器零新增依赖、视觉与展示端暖现代风格一致，这样包体不膨胀、体验不割裂。

## Implementation Decisions

- **改造对象**：现有全局灯箱单例（组合式状态 + 根组件挂载层），在其上扩展查看器能力；展示端详情页相册分组与**管理端相册浏览器**均经同一全局入口打开，自动获得全部能力。单一全局单例架构不变。
- **视图变换模型**：单一变换状态（缩放倍率、平移偏移、旋转角度），全部经 CSS transform 应用于图片；缩放范围 1x–4x，1x 即"适合窗口"（沿用现有最大宽高约束）；所有变换在翻页、关闭时复位；旋转 90° 步进、仅内存态、不落库（相册原图的 EXIF 方向已由图片管线转正，旋转是纯观看辅助）。
- **输入通道与冲突消解**：桌面滚轮=缩放；双击=1x↔2x 切换；键盘保留 ESC 关闭与 ←/→ 翻页，**不新增**快捷键。移动端单指：1x 时横向滑动超阈值翻页（否则回弹），放大态单指只平移；双指捏合缩放并跟随平移，不做双指旋转。触摸事件在灯箱层阻断冒泡，避免触发背景手势。
- **可见控件**：桌面两侧半透明圆形箭头 + 底部居中胶囊工具栏（缩小、计数 n/N、放大、适合窗口、旋转、关闭）；手机隐藏侧箭头（滑动替代），工具栏保留；单张无组时箭头与计数隐藏。控件样式遵循 ADR-0001 暖现代语言（半透明深底、白描线、圆角胶囊）。
- **过渡动画**：翻页为轻量淡入 + 轻微位移（沿用现有灯箱入场动画的节奏），不做整页滑动画廊（与缩放/平移状态叠加复杂，收益低）。
- **失败态**：现有加载失败兜底文案保留，失败照片不阻断翻页与工具操作。
- **高清档提清**：后端高清档默认尺寸 1600 → 2600（配置项默认值与部署环境样例同步）；缓存键纳入尺寸数值，配置变更后旧缓存自然失效、按需重建，无需人工清理。
- **实现方式**：手写（指针/滚轮/触摸事件 + CSS transform），零新增依赖，不引入第三方查看器库。

## Testing Decisions

- 唯一自动化测试接缝仍是后端 HTTP API（本仓库既有约定：前端不写自动化测试）。图片管线已有 API 表面测试为先例：新增/调整断言覆盖"高清档尺寸上限为配置值、缓存键随尺寸配置变化而失效重建"。
- 前端交互（滑动阈值、捏合、双击、复位时机、控件显隐）靠浏览器人工验收：桌面 1440 与移动 390 两档视口，覆盖翻页、缩放、平移、旋转、失败态与单张无组态。完成后由主代理实际起服务自验一轮。
- 前端类型检查（vue-tsc）必须零错误作为最低回归门槛。

## Out of Scope

- 原图档（original）按需加载——放大超过 2600px 档的极致清晰度，列入 v2 候选。
- 双指自由角旋转、自由角度旋转。
- 迷你导航窗（缩略图视口指示器）。
- 旋转角持久化保存。
- 键盘 +/-/0/R 等新增快捷键。
- 桌面触摸板手势精细化（如惯性、边缘翻页）。
- 前端自动化测试（沿用仓库既有决定）。

## Further Notes

- 访谈中确认的关键取舍：滚轮只能归属一个操作——归缩放（高频）而非翻页；放大后平移优先于翻页（防误触跳张）；快捷新快捷键被否——用户偏好最小键盘面。
- 部署提示：`full_size` 上调后首次浏览会触发一轮重建缓存，属预期行为。
